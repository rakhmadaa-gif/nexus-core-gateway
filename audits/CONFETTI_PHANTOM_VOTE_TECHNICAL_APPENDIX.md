## 1. The Vulnerability (now public)

`Governor.castVote()` in `packages/forge/src/governance/Governor.sol` (v6.21) never verified that the voted-on `proposalId` was ever proposed:

```solidity
function castVote(uint256 proposalId, uint256 numVotes) public payable returns (uint256) {
    uint256 actionCost = _determineCorrectAmountSent(Actions.Vote, numVotes);
    if (proposalIsDeleted[proposalId]) revert CannotVoteOnDeletedProposal(); // only a *deleted* flag
    _distributeCost(actionCost);
    return _castVote(proposalId, msg.sender, numVotes);
}

function _castVote(uint256 proposalId, address account, uint256 numVotes) internal returns (uint256) {
    if (state() != ContestState.Active) revert ContestMustBeActiveToVote();
    if (numVotes == 0) revert NeedAtLeastOneVoteToVote();
    // <- NO check that proposals[proposalId].exists
    _countVote(proposalId, account, numVotes);
}
```

`propose()` sets `proposals[proposalId].exists = true`, but the voting path never consulted it. A **phantom** (never-proposed) ID — e.g. `hashProposal` of an arbitrary `ProposalCore` never submitted — accumulates votes in `proposalVoteStructs`, `votesToProposalIds`, and `sortedRanks`. At contest completion, `VoterRewardsModule.getProposalIdOfRanking()` resolves the ranking through `sortedRanks` → `getOnlyProposalIdWithThisManyVotes`, returns the phantom ID, and `release(voter, ranking)` pays `totalReceivedForRanking * voterVotes / proposalVotes` to the phantom's voters.

## 2. Proven Impact (Foundry PoC, 2/2 PASS on vulnerable v6.21)

**Path A — Stealing organic voters' rewards (creator-only contest, `anyoneCanSubmit = 0`):**
- Real proposal gets 100 organic votes @ 0.01 ETH → 1 ETH in the rewards pool (`percentageToRewards = 100`)
- Attacker who **cannot even submit** computes the hash of a never-submitted proposal, votes 101 on it (cost 1.01 ETH)
- Phantom takes rank 1 → attacker claims the **entire 2.01 ETH pool**, net **+1.0 ETH** (the organic voter's full contribution). The organic voter's `release()` reverts with `AccountNotDueNativePayment`

**Path B — Stealing creator-funded rewards from an empty podium rank:**
- Creator funds 10 ETH pool, ranks 1-3 shares 50/30/20, only two real entries
- Attacker's phantom takes **empty rank 3 with a single 0.01 ETH vote** → claims **2.012 ETH** at completion (**~201x ROI**)

Same applies to ERC20 rewards (`release(IERC20, voter, ranking)`).

## 3. Fix (shipped by maintainer, verified)

Commit `5851d715` "bugfix: check proposal exists (#6311)" — merged 5 hours after the private report, 2026-09-11:

```solidity
if (!proposals[proposalId].exists) revert ProposalDoesNotExist();
```

in `_castVote`, plus version bump 6.21 → 6.22, bytecode regeneration, and a maintainer-authored regression test (`testVoteOnNonExistentProposal`). Both PoC paths mechanically confirmed closed on fixed code (both tests revert with `ProposalDoesNotExist()`).

**Closure-day sweep (2026-09-15)**: fix verified present in `staging` at `Governor.sol:484`.

2. **AST-level review, no regex heuristics**: full manual read of all 8 contract files (1403 lines) with EVM state-machine reconstruction of the vote → rank → reward-settlement path.
3. **Invariant analysis**: ranking and reward settlement assume every ranked proposal passed through `propose()`. The unenforced invariant — `exists` never checked on the vote path — is exactly the kind of gap that survives static pattern-matching but falls to state-machine tracing.
4. **Foundry PoC discipline**: no submission without a passing mechanical proof; both exploit paths quantified (net theft, ROI) before reporting.
